# Antonella's Takeaway

Learning by doing is the best. Reading about branches, commits, and pull requests only got me so far — it clicked once I actually created a branch, staged and committed a change, pushed it to GitHub, and opened (and closed!) a real PR myself.

Going forward I'll treat GitHub as a hands-on tool, not just a concept: branch to try things safely, commit save points as I go, and use pull requests to propose changes. Mistakes are recoverable, so the fastest way to learn is to just try it.
